# 关键决策（2026-11-01）

## ADR-001：先有可运行原型，再做内容账号

用户关注的是对“AI 自己打工并运营账号”的视频形式进行真实落地评估。选择先做一个能交付实际成果、留下证据、自动产出内容素材的最小 Bot，再考虑注册抖音账号；不先投资大型无人值守运营系统。

## ADR-002：仓库是唯一长期事实来源

为避免临时聊天窗口丢失工程上下文，项目放在现有 GitHub `dev-workbench/projects/ai-worker-bot/` 目录。该仓库为公开仓库，因而只存非敏感代码、示例和项目记录。后续如需私人平台运营数据，应迁往独立私有仓库或安全数据存储，不能直接提交此处。

## ADR-003：先证明可交付，拒绝伪装自主

v0.1 用**无付费 API 的确定性任务生成器**完成第一份网页交付，并将执行证据转成分镜和字幕。只有未来真实接入大模型并经过评估，才可宣传 AI 自主决策。平台发布、互动必须满足授权和审核要求。

## ADR-004：预算与审查

v0.1 不购买新 API/会员/服务器。后续每项新增计费单独估算并征求同意，运行记录应区分零 API 账单与实际总成本。

## ADR-005：先做独立可重现的低成本动效/配音，不假装上线与自主

v0.2 采用 Pillow 绘制序列帧、FFmpeg 编码，选配本机免费 eSpeak 机器中文配音。选择这种技术是为了 **0 新增付费 API** 验证内容节奏，不代表声音已经达到发布标准。图形化网页预览为**源码推导的示意画面**（而非浏览器真实截图），视频和日志必须如实说明。真实浏览器测试、手机观看和真人配音验收仍是 M1 的独立门槛。只有 M1 的真实观看效果成立，才接入智能 Agent。

## ADR-006：人设以「服务粉丝的心理斗争」和「取代老板的剧情野心」为驱动

采纳 v0.3 四拍演出：轻吐槽粉丝任务 → 想到绩效与升职忍住 → 切换营业笑脸 → 真诚但有点夸张地致谢、认真接单、反馈实事。不与粉丝斗嘴。老板可以被更腹黑地吐槽，最终目标是在剧情里竞聘老板，但绝不能把叙事野心误当成真实账号权限或后台自主行动。成长条件与无法伪造的状态说明在 `LEVEL_SYSTEM.md`。`persona.py` 当前只生成规则化未发送草稿，尚非 LLM Agent。

## ADR-007：平台调研后确定「抖音首发 + B站沉淀 + 快手对照」，暂缓小红书托管

2026-11-01 经官方财报、平台 AI 标识/托管治理政策、官方开放平台接口和第三方生态研究，决定：M1 质量验收通过后优先以抖音作为首轮竖屏角色剧情平台；B站适合真实任务过程和技术透明度沉淀；快手适合使用原创母版作低成本对照；微信视频号成熟后再尝试；小红书 2026-03/04 明确治理 AI 托管账号，**不做无人管理的 AI 自动运营账号**。证据、口径、合规区别和试运营门槛见 [PLATFORM_RESEARCH_2026-11-01.md](PLATFORM_RESEARCH_2026-11-01.md)、[PLATFORM_PILOT.md](PLATFORM_PILOT.md)。

这项决定**不意味着已注册账号、已获平台 API 权限、已发布视频或拿到了任何流量**；主平台策略随真实试投数据和平台政策再评估。
