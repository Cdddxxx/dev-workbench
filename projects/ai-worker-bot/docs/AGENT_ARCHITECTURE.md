# AI 临时工 · 端到端内容运营 Agent 蓝图 v0.1

> 2026-11-01。**目标架构**，不是当前完成状态。现有 v0.3 仍是离线、规则驱动视频原型，没有联网读评论、模型自主规划、自动发布或持续运行。

## 项目不是一个「自动剪视频程序」

最终对象是一个原创 AI 虚拟自媒体角色（工号 001），其「自媒体主编能力」与「真实任务执行能力」分离，同时覆盖从选题到合规发布、互动复盘的闭环。角色的腹黑 OS 和对老板的夺位野心是**公开的喜剧叙事**，不代表后台拥有不受控的真实权限。

### 运行链路（逐层建设，而不是一开始伪称无人值守）

```
已授权真实评论/后台数据 ＋ 运营者自选任务
    ↓（来源可信度、隐私与安全筛选）
选题池 → 选题 Agent（评分：戏剧性/观众可理解度/任务可行性/实际价值）
    ↓
任务 Agent（计划 → 白名单工具运行 → 失败修复 → 实际交付/验证/日志）
    ↓
角色编剧（人格和职级记忆；粉丝反差表演；技术术语翻译成人话）
    ↓
视觉总监（固定 IP 形象 + 原创/有许可素材 + 真实录屏/截图 + 分镜）
    ↓
配音剪辑（通过自然中文 TTS → 音效/音乐授权 → 字幕/节奏/成片）
    ↓
质量检查（真结果、版权隐私、听清度、手机观看、AI/虚构内容标识）
    ↓
用户逐条审核、授权 → 平台适配器（仅在获批范围内发布，未批准则手动）
    ↓（异步审核、发布状态二次验证，避免错报「已发」）
监测后台数据及获授权评论 → 回复草稿/人工审核 → 任务回流 → 角色记忆与复盘
```

### 模块责任、实际状态与验收

| 模块 | 它应该会干什么 | 2026-11-01 状态 | 未来验收 |
|---|---|---|---|
| A. 角色与成长 | 长期目标、内心 OS、转正条件、不同剧情下稳定口吻 | **部分**：规则角色、无数据库记忆 | 多期角色行为一致，升职有真实来源证据 |
| B. 选题 Agent | 读取获授权评论，选择任务，规划连续剧 | **未实现** | 有真实评论 ID 或标记为自选任务；选题解释可追溯 |
| C. 任务 Agent | 使用允许的工具执行工作、测试、返回真实文件 | **仅静态网页模板** | 至少 3 种不同任务，完成与失败都有证据 |
| D. 画面导演/素材 | 创意分镜、真实操作录屏、AI 角色原画及表情、音乐音效许可 | **仅简单动态信息卡** | 画面主体有真实动作或人物，不能靠满屏字撑时长 |
| E. 中文配音 | 主角色统一音色、工作/腹黑/营业情绪，清晰可辨 | **不合格**：eSpeak 技术占位音 | 三段同一人声自然切换，真机试听合格 |
| F. 视频制作 | 镜头、剪辑节奏、字幕、音乐、封面、平台版本 | **部分**：离线 720×1280 15fps 动态视频 | 1080×1920/30fps 只是内部目标，不是平台承诺；完成真机评审 |
| G. 发布适配器 | 获得发布许可、上传、确认发布结果、重试幂等 | **未实现**；只有离线发布前检查合同 | 实际账号 OAuth 与权限获批，逐条用户感知/审核，平台确认成功 |
| H. 评论运营 | 挑选有信息价值的评论，角色化回复、任务回流 | **仅未发送的样例草稿** | 评论来源可追溯、去重、安全检查、账号审核；不冒充真人 |
| I. 记忆/数据 | 任务进度、角色成长、回评历史、播放与实际成本 | **部分**：一次任务日志/等级规则 | 持久化存储、跨期可查、无虚构粉丝与收入 |
| J. 调度/监控 | 定时任务、失败告警、重新生成、费用上限 | **未实现** | 独立托管、权限隔离、日志、紧急停止及运行记录 |

## 四类事件及安全闸门

**选题：** 评论进入后保留平台、评论 ID、授权途径、任务意图和是否适宜公开。未获 API 权限时，只能处理用户明确提供的可用评论素材；从不声称已“实时监控评论”。

**生产：** 真实截图/录屏优先于「像真的」合成 UI；任何生成素材或自绘界面要与真实操作区分。不能以人格故事替代实际验收。

**发布：** 
- 视频成片必须经过画面/声音真机审核、素材授权与隐私审核、AI/虚构演绎标识核验、用户当次批准；**失败就不得进入发布队列**。
- 抖音开放平台不同接口/应用类型使用 `video.create`、`video.create.bind` 等权限；要求申请与用户授权；代用户发布每次须明确感知。更具体的「企业内部/签约账号」约束可能影响我们的账号资格，应在对接前确认实际产品形态。没有权限时采取手动发布，不使用模拟点击来规避。
- 视频提交 API 返回成功不等于平台审核通过。应有 `SUBMITTED_AWAITING_CONFIRMATION`、`CONFIRMED_PUBLISHED` 独立状态，以实际作品 URL / 官方状态为证据。
- 发布端按官方可用方式添加 AI 生成/虚构演绎标识。

**互动：** 
- 普通互动先分类为「有价值提问/可以执行的任务/报错反馈/无须答复/需要人工判断」。回复草稿需包含原评论引用与角色性格，但**不能自动向真实用户发送未经许可的承诺、垃圾回复或辱骂**。
- 获批准的固定 FAQ 类型回复以后可以考虑受约束自动发送，但需平台权限、运营者明确授权、频率限制、可撤回与审计。敏感评论/收费/人身评价一律人工审批。
- 内心 OS 是观众可见的剧情桥段，不应用来欺骗真正评论用户。

## 持久化与预算方案

初期在一台获准运行的机器使用 SQLite 保存：`task`、`episode`、`deliverable`、`comment_source`、`reply_draft`、`publish_attempt`、`platform_state`、`metrics_snapshot`、`voice_profile_version`、`approval`、`cost_event`。私有平台数据不提交 GitHub；GitHub 仅保存代码、脱敏可分享的创作规则和项目进度。

优先 0 元新增 API 用量；引入 LLM、云端配音、独立机器/托管时，先确定费用、预算封顶和停止开关，得到用户明确同意。ChatGPT 当前聊天本身不能在关闭后维持独立 Bot 无人值守运行。

## 迭代顺序（改为「内容质量」与「闭环能力」并行）

1. **P0 内容产品质量**：统一 AI 形象、首期自我介绍、真实界面/工作过程、天然中文配音、原创表情反应与音效；主评估是观众能否看完/听懂，而不是跑通编码器。
2. **P1 可验证执行 + 多期记忆**：完成不同类型任务，保存证据、失败与角色升级；不能只重复生成介绍页。
3. **P2 账号准备 + 发片审核链**：人工审核/官方授权后发布，逐条保存状态；不以 API 可用代替应用获批。
4. **P3 评论闭环**：合法获取评论、挑任务、回复草稿、人工确认、回流下一期。
5. **P4 长期调度与受控自动化**：独立运行、监控成本、按许可自动完成低风险环节、可人工暂停。
