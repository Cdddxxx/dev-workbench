# 粉丝关系与里程碑记忆 — 设计规范 v0.1

> 产品功能设计，**当前尚未接入真实平台数据/持久数据库**。不把“第一位粉丝”做成唯一玩法。所有真实观众信息仅在合法授权、目的明确、最小必要、私有存储与可删除的条件下处理。

## 目标

让工号 001 不是每期忘掉一切的播报机：它能够记得**真实发生过、已核实、在当前互动中有用**的共同经历，在适当时刻自然提起，形成老朋友感；又不过度关注、冒犯、识别或“监视”观众。

**两层分开**：
A. 事实事件：平台可验证、有来源和时间戳、明确什么能证明/不能证明。
B. 剧情表达：依据已核实事实生成符合人设的 OS、营业笑脸和互动话术，不增加虚构事实。

## 不限于“第一个”的可落实场景

| 场景 | 必要数据和事实来源 | 合适的个性表达 |
|---|---|---|
| 最早可验证评论者再次留言 | 已获授权获取的原评论 ID、作者稳定标识、观察时间、可回溯证据 | “我刚上岗时就看过你的留言，还记得你当时给我出的那道题。” |
| 指出第一个真正修好的 Bug | 评论/任务来源 + 修复前后证据 + 与作者匹配 | “上次你抓的 bug 我修好了，这次先别让我丢人。” |
| 第一次真正执行观众挑战 | 任务ID、授权来源、执行结果和作品链接 | “这位甲方又来了。上次那单让我差点加班到天亮。” |
| 几次后再回来的熟面孔 | 同平台经授权的稳定 ID、之前的可公开互动历史 | “哟，老朋友。上回那句我还记着呢。”（避免夸张监控感） |
| 首次晋升的参与观众 | 有来源的公开投票/建议/评论及参与资格 | “我转正的时候你投过票，这回要不要再给我打个分？” |
| 真正的第一次点赞/关注 | **平台实际提供能够验证顺序的记录时**才可认定 | 能确认才说“第一位”；否则说“最早支持我的观众之一” |
| 一次共同失败与反转 | 任务失败记录、后来重新完成的记录 | “那次翻车你在场。这回总算交卷了。” |
| 账号日龄、重大里程碑回顾 | 真实已发布视频时间、内部里程碑及经审核统计 | “100 天前我还只会生成模板，现在我终于能……” |
| 被观众取了公认昵称 | 有证据的多次公开互动、审核确认 | 角色自嘲昵称；**不要未经同意给用户贴负面标签** |

不应在没有官方可信时间顺序和完整覆盖的情况下“倒推第一个关注者”。唯一用户名/头像/相似言辞都不能当稳定身份标识；跨平台默认不关联同一个人。

## 事件模型（先设计，后在私有存储实现）

最小事件字段：
- event_id：内部随机 ID
- platform：来源平台
- subject_key：在**私有**存储中由平台稳定 ID 派生的本地伪名化键（密钥与数据库分离）；平台不提供稳定 ID 时不能跨期认人
- kind：comment / task_suggested / task_accepted / task_verified / bug_reported / bug_fixed / milestone_participation / consent_change 等
- source_ref：允许使用的事件原始 ID 或受限制的来源引用（不在公开仓库）
- occurred_at / observed_at：事件发生时间与 Bot 实际观察到的时间；不能混淆
- status：verified / unverified / fictional_test；只有 verified 才能作为真实记忆引用
- proof_summary：支持此结论的最小证据，不抓取/永久保存不必要的私聊和个人画像
- use_scope：允许用在当前回复/未来互动/视频公开提及的范围，默认保守
- expires_at / revoked_at：存储有效期与撤回删除记录

人物叙事也可保存**不含个人信息**的里程碑状态，如第 1 条发布作品、失败/修复经历、总任务完成数和角色晋升。

## 互动决策

只有以下条件同时满足才触发个性化回忆：
1. 本次互动来自**经授权、可核实的同一账号**，而不是同昵称或跨平台猜测。
2. 回忆与当前问题相关，重提有价值；不要看到老粉就每次强调“我记得你”。
3. 事件为 verified；来源丢失或不确定时改用不涉及身份/先后的普通回复。
4. 可用于公开回复；如果要把观众名字/评论放进视频，按平台规则与必要的同意处理。
5. 有冷却与频率限制，如 5 次回复最多 1 次提旧事（**内部初始参数，实际可调整**）。
6. 用户表达不想被记住或请求删除时要停止使用并从私有存储清除相应可删除数据，保留最少必要的安全审计。
7. 对未成年人、敏感个人属性、私信细节、真实地址等不做关系画像，也不用“你失踪很久了”等可能造成压力的说法。

**禁止**为了引导继续互动而夸大亲密关系，禁止把情绪价值变成精准情绪操控；真诚感谢和角色幽默就足够。

## 三个早期可验证用例（不需要真实 API）

1. 用明确标注为 SYNTHETIC 的事件：观众 A 首次提了 bug → 记录修复 → A 再留言 → 生成符合角色的草稿，引用正确事实。测试不同昵称但同 ID、同昵称不同 ID。
2. “第一位关注者”没有可靠记录 → 不准调用 FIRST_FOLLOWER 里程碑文案，生成保守回复。
3. 观众撤回记忆许可/要求清除 → 阻止所有历史个性化回复，并删除相关身份事件；重复消息不应恢复历史。

## 从离线走向线上

MVP：纯本地模拟事件 + SQLite（私有）+ 查询接口 + 冷却/删除测试。正式平台接入前要先确认官方 API 可提供的字段、授权条件、保留期限，编写合法的数据采集流程。账号没有公开评论权限时可使用账号持有人授权、合法提供的评论样例，不使用绕过权限的抓取。待平台权限获得并审查后，再将个人记忆接入已审核的回复草稿工作流。**当前 0 条真实粉丝记忆、0 次自动回复。**
