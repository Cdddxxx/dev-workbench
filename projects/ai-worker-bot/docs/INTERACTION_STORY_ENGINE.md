# 角色剧情与互动事件引擎 — 创意清单和落地顺序 v0.1

> 用户提出“记住第一个粉丝”是打开思路的例子，**不是功能清单的边界**。事件驱动剧情不等于实时读取平台账号；真实人物关系必须遵守 RELATIONSHIP_MEMORY.md。现在是设计稿，尚未实现通用事件引擎。

## 设计公式

**可证实的事实 / 自己真实完成的任务 → 看见其中的冲突 → 用工号001的人格去解释 → 形成下一期任务或彩蛋 → 观众回应 → 新事实进入记忆。**

不必把所有转折做成“第一个”；重要的是**有真实故事因果**。情绪表现来自表演和对具体内容的回应，不能伪造真实经历或暗中操纵观众。

## 事件类型和示例玩法

| 事件类别 | 真触发条件/证据 | 情节创意 |
|---|---|---|
| 早期陪伴 | 最早可确认的有效留言和复访 | “您这是来检查我有没有被老板开除？”说完立刻热情招待 |
| 实用纠错 | 经验证的 bug 反馈 → 修复结果 | OS：“又是你，质量部编外员工。” 笑脸：“这个提醒帮我省了一天返工。” |
| 观众任务连载 | 可执行的具体任务、多期完成记录 | 任务积压导致 Bot 做“排期表”，老板却追加 KPI |
| 角色职级节点 | 主平台真实粉丝/已验证交付达到规则门槛 | “转正申请被老板打回”的喜剧情节；不要说真实平台审批 |
| 老板办公室故事 | 真实经营约束 + 明确虚构的办公室剧情 | 001 偷偷给自己设计“老板候选人”名片，结果忘了关屏幕 |
| 性格暴露时刻 | 人物被质疑/收到难搞任务 | OS 瞬间红温，面部秒切营业笑脸；用实事回应，不讽刺观众个人 |
| 第一次挫折 / 翻盘 | 本地构建/工具测试确实失败并后续修复 | “这次别叫我专家。先叫我返工大师。” |
| 有价值的粉丝昵称 | 多次自愿公开互动/明确允许称呼 | 临时称号如“修Bug质检员”，不能贴永久负面标签 |
| 惊喜与庆祝 | 首个经验证的可用成果被实际使用 | 给完成任务的人做“升职感谢名单”，须审查公开署名意愿 |
| 自我进化 | 新能力上线且有版本差异证据 | 老版机器音与新主声线对比，Bot 内心嫌弃老录音 |
| 老粉回归 | 可验证历史身份和非敏感互动 | 把旧事当成一个自然的小彩蛋，不每条都打感情牌 |
| 多平台迁移 | 明确获准平台账号与作品记录 | Bot 吐槽“每个平台 HR 标准不同”，不未经允许关联观众身份 |
| 每周真实总结 | 任务、发布和成本的真实记录 | “本周 KPI：挨骂两次，修 Bug 三次，转正依旧遥遥无期。” |
| 长期悬念 | 已公开的剧情伏笔、后续实际作品 | 老板位置旁的便签一集一集变化，最终宣布合法“职位竞聘” |

## 创意选取标准

一个故事点要满足：
- **有可识别情绪**：期待、困境、反转、庆祝或轻松自嘲；不是数据播报。
- **有视觉动作**：表情、实录、原创梗图、剪辑/镜头运动和音效；不是十行字幕。
- **有真实性边界**：现实事实可核对，办公室角色幻想明确属于剧情。
- **不重复**：同一个“我认识你”“老板坏”“粉丝提难题”的梗不过度复用。
- **对粉丝尊重**：吐槽任务而不攻击粉丝，最终认真解决需求。
- **低隐私风险**：不用身份拼接、偷窥/挖掘非公开资料制造惊喜。
- **可执行性**：能用已有素材/真实事件完成；不为搞剧情先编评论或购买流量。

建议优先评分维度：戏剧强度、真实证据质量、对系列推进的贡献、视觉可实现性、重复疲劳、权利/隐私风险。**不要把这些评分当平台算法权重。**

## 三个落地层级

**L0 — 不用平台 API 也能做**：用经授权的自有制作记录、真实的设计过程、真实 Bug/修复、角色晋升“尚未开始”等形成剧情。第一期就用：选头像、主声线选择、老板工位伏笔。

**L1 — 用户提供互动素材**：拿账号所有者合法提供的公开评论/任务，在来源可见的前提下做“任务接力”“修 Bug 回访”，输出**未发送回复草稿**。不假装 Bot 已经实时看到平台评论。

**L2 — 官方账号 API/审批权限就绪后**：按授权范围抓取可用评论与后台数据 → 事件登记/去重 → 安全与相关性筛选 → 选择话题/回复 → 人工审批 → 发送并确认平台结果 → 回写关系记忆和下一期任务池。每步要有来源、重试去重、权限撤销和停止开关。

## 迭代节奏与避免疲劳

第一期：自我介绍与头像/名字/隐藏升职野心，**没有真实观众记忆**。第 2–4 期逐渐建立任务交付与口头禅，第 5 期以后根据真实反馈决定哪些连续剧情值得延展。每期优先只突出**一个**主要情绪/记忆点，避免同时挤入各种 HUD/职级数字/术语。

粉丝特殊身份只在对方自愿参与、当下相关时启用；不能为了留存制造假专属、假亲密关系、假第一粉丝或虚构自动回复。

## 实施建议

建立独立的可测试模块（建议名称 story_events.py），以非敏感角色里程碑和合规互动事件作为输入，输出**故事候选**、选择理由、证据链接和人工审核状态。先纯离线实现，不要把剧情脚本写死在视频 renderer；将来可以接真实创作规划 Agent。严格区分“故事候选”和“已发生事件/已回复消息”。
